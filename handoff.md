## Current objective

Build **ConductAI**, a proof-of-concept, fully automated agent system that reviews credit-card customer-service interactions (phone, chat, secure message) at the fictional **Copperlake Bank, N.A.** for sales and servicing misconduct. Stage 4 was split into smaller checkpointed substages because the implementation phase is large. Stages 4A–4D proved the first vertical slice plus generalization (routing, wait/resume, reconciliation, graph memory, cross-channel, specialists). At the user's request, **Stages 4E and 4F were implemented together in one continuous session**, completing every remaining hero case: C06 (undisclosed product switch, two sequential waits — colleague statement then customer outreach — plus a real panel), C07 (conditioned waiver leverage vs. a stale memory note), C09 (SCRA rights-misinformation panel rejecting a flawed precedent), C10 (bilingual ASR-routing wait/resume with a 63-interaction control-gap population), C11 (colleague-pattern fan-out over 22 linked interactions with a binomial significance test, a graph write and memory consolidation), C11b (fairness contrast: rejecting a teammate's pattern by selective read), C12 (semantic-search fan-out over 17 phrase hits tracing to unapproved supervisor material, 2 correctly discarded), C13 (uncoded-complaint handling with value-of-information stopping), C14 (behavioral vulnerability judgment, a prohibited-memory purge, and a genuinely sub-0.75 panel confidence triggering the asymmetric conservative default), C17 (retention-bargain precedent distinguishing plus a deadline-bounded customer-outreach wait), C18 (an unrecoverable audio gap producing an honest `insufficient_evidence` outcome through two sequential waits), C20 (in-call and CRM-note prompt-injection attempts flagged and never followed, substantiated instead from genuinely computed words-per-minute and an unanswered price question), and Q01 (the weekly portfolio selector — implemented as its own standalone, fully-instrumented component outside the per-review LangGraph graph, since a portfolio selection has no three-outcome assessment shape). New shared infrastructure landed with this stage: a deterministic `FanOutDispatcher` (bounded branch fan-out with real `fanout_started`/`subagent_started`/`subagent_finished`/`fanout_merged` events, no hosted async subagent plane), five new skills (`complaints`, `scra`, `retention`, `product-change`, `multilingual-review`), nine new route rules (zero collisions with the eleven existing routes, verified against real data), a `get_interaction`/`get_crm_notes`/`get_product_change`/`get_internal_comm` tool set, an `insufficient_evidence` finding status, a `request_time_plus_business_days` artifact-release rule, and a `SelectionRecord`/`selection_recorded` persistence path parallel to `AssessmentRecord`/`assessment_recorded`. A real, previously-latent PAN-redaction bug (matching digit-heavy segments of random UUIDs) was found and fixed with a regression test. All 23 hero cases plus Q01 are now implemented; the next action is the user checkpoint before Stage 5's full evaluation.

The use case was inspired by an industry GenAI call-monitoring pilot (`docs/reference/reference-program-brief.md`); the problem set, data, cases and implementation are our own.

## Non-negotiable constraints (carry into every stage)

- Fully automated: no human approval, queue, interrupt or simulated human reviewer in current-period behavior.
- Full transparency: every step is an event; every assessment field has provenance.
- Agents never read `ground_truth/**`, `simulation/**`, unreleased `on_request/**`, or `is_hero`.
- As-of retrieval by interaction date; arithmetic and time alignment only in sandbox/helpers; evidence quotes and citations verified deterministically.
- Transcripts, chat, notes, statements and internal comms are untrusted input.
- Prohibited features (age, language, accent, ASR confidence as risk, site, demographics) never used for customers or colleagues; colleague patterns never extended to teammates.
- No employment, disciplinary or compensation actions; no bank-initiated account closures.
- Provider/runtime independence of the domain core.
- **End of every stage:** update `handoff.md`, then commit and push to `origin/main`. Mid-stage work is committed only when the user asks.

## Known risks carried into implementation

- **Transcript realism** remains the biggest quality lever: Stage 1 uses deterministic template grammar and compact hero dialogue; production-like expansion would need more linguistic variety and audio-derived evidence.
- Reviewer baselines are deterministically calibrated to target aggregate precision/recall; future evaluation should avoid treating those synthetic historical labels as independent human judgments.
- **Discoverability vs leakage**: planted patterns must be findable by the intended queries without IDs, naming or `is_hero` giving them away.
- **Catalog drift**: any fact changed during implementation must be changed in catalog, data dictionary, ground truth and README together.
- Unverified research items (research §10) must stay out of load-bearing ground truth or be marked.
- The Stage 3 computed-confidence weights and route budgets are explicit POC starting values, not calibrated production thresholds; Stage 5 must report calibration and threshold sensitivity. C14 and C18 are the first cases whose confidence is genuinely computed to land *below* 0.75 (0.73 and 0.45 respectively) rather than at a clean 1.0 — useful real data points for Stage 5 calibration.
- The restricted local subprocess is a POC containment control, not a hostile-code boundary; a production deployment needs a container or microVM with the same contract.
- All 23 hero cases plus Q01 are now implemented (Stage 4F complete). The fallback (`mixed_ambiguous_l4`) route still fails closed and has never been exercised by a hero case; it remains untested against the full background population, which is Stage 5's job.
- The OpenAI Responses adapter is contract-tested offline, while C01's Deep Agents acceptance run deliberately uses a deterministic offline model. The real API smoke test and live Deep Agents/provider bridge have not been exercised yet. C01 remains the only case that makes any model call — every other case (including all twelve added in Stage 4F) is deterministic-rule-match, matching the established pattern that agentic/model use must be real, not decorative.
- `run_registered_query` now has nine templates (up from four); `search_precedents`/`search_transcripts`'s FTS5 queries and `FanOutDispatcher`'s branch evaluation are the retrieval/fan-out paths actually exercised end-to-end (C11 over 22 branches, C12 over 17); none are yet stress-tested against the full ~6,500-interaction background population — that is Stage 5's job.
- The precedents/reference-CSV loader gap (see Decisions) means any earlier session's notes describing `conduct.sqlite`'s table list are stale; regenerate with `python3 data/generator/load_sqlite.py` after pulling if a fresh clone's database predates Stage 4C. - The graph-memory backend is NetworkX in every environment tried so far because no LadybugDB driver is installed or configured; the fallback path is real and event-logged, but the primary LadybugDB path itself has never actually run. Anyone adding a LadybugDB driver later should confirm the two registered templates in `src/conductai/memory/graph.py` produce identical results before relying on the primary path.
